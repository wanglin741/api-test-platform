# 开发环境

> 后端依赖选型、基础设施 compose、测试运行器的落地说明。[T1] 引入,后续工单在此增量补充。

## 前置要求

- Python 3.11 + [uv](https://docs.astral.sh/uv/)
- Docker(含 compose v2)
- Node ^22.18.0(前端,本 MVP 阶段暂不涉及)

## 一条命令起基础设施

```sh
cd backend
docker compose up -d     # PostgreSQL 18 + Redis 7,只含基础设施
uv sync                  # 安装依赖到 backend/.venv
uv run pytest            # 测试应全绿
```

应用进程本地跑(不在 compose 里),便于热重载与调试。端口被占用时用环境变量错开:`POSTGRES_PORT` / `REDIS_PORT`,此时同步修改连接串(见下文环境变量)。

## 依赖选型

| 类别 | 选型 | 版本要求 | 依据 |
|---|---|---|---|
| Web 框架 | FastAPI + uvicorn[standard] | ≥ 0.135 | 设计文档要求 SSE 可用 0.135+ 原生支持(已实现,`fastapi.sse`) |
| HTTP 客户端 | httpx | — | 引擎 D2:自研异步引擎的请求层,`MockTransport` 也是引擎测试的关键缝 |
| ORM | SQLAlchemy 2.x `[asyncio]` | — | D6:API 用 async engine;worker 用同步 Session,两个驱动都要装 |
| 数据库驱动 | asyncpg(API)+ psycopg[binary](worker) | — | D6:asyncpg 不能跨事件循环复用,worker 全程同步,故双驱动 |
| 迁移 | Alembic | — | 全平台唯一迁移历史 |
| 任务队列 | Celery 5.6+ `[redis]` | ≥ 5.6 | §5 Celery 配置用到 5.6+ 的 `worker_disable_prefetch` |
| Redis 客户端 | redis-py | — | 进度流 / 取消标志(首版仅 broker 依赖它) |
| 配置 | pydantic-settings | — | Settings 类,API 与 worker 共用 |
| JSON 解析 | orjson | — | 执行引擎 §4:响应体先 orjson 解析再走 JSONPath |
| JSONPath | jsonpath-ng | — | 提取器默认实现 |
| 测试 | pytest + pytest-asyncio | — | `asyncio_mode = "auto"`,异步测试免装饰器 |
| 边界守护 | import-linter | — | 执行引擎 §1:`engine/` 禁止 import fastapi/celery/sqlalchemy,[T2] 起生效 |

锁文件 `uv.lock` 入库,保证所有环境依赖一致。

## 应用配置

统一走 `app/core/config.py` 的 `Settings`(pydantic-settings),环境变量前缀 `APITEST_`,支持 `backend/.env`(已 gitignore,不提交):

| 变量 | 默认值 | 说明 |
|---|---|---|
| `APITEST_ENV` | `dev` | dev / test / prod |
| `APITEST_LOG_LEVEL` | `INFO` | 根日志级别;API / worker / pytest 三类进程共用,统一格式输出到 stderr |
| `APITEST_DATABASE_URL` | `postgresql+asyncpg://apitest:apitest@localhost:5432/apitest` | API 进程(asyncpg) |
| `APITEST_DATABASE_URL_SYNC` | `postgresql+psycopg://apitest:apitest@localhost:5432/apitest` | worker 进程(psycopg) |
| `APITEST_REDIS_URL` | `redis://localhost:6379/0` | broker / 进度流 / 取消标志 |
| `APITEST_BODY_MAX_BYTES` | `65536` | 响应体内联上限,超出截断(D4) |
| `APITEST_ENV_VAR_WHITELIST_PREFIXES` | `('TEST_',)` | `{{$env.X}}` 可读的进程环境变量前缀白名单 |

compose 里的默认账号密码与上表默认连接串一致(`apitest`/`apitest`),clone 后无需任何额外配置即可跑通。

## 测试运行器

`uv run pytest` 默认跑全部非 e2e 测试(纯内存,毫秒级)。e2e 测试(真实 socket、真实服务、真实 PG)标 `@pytest.mark.e2e`,默认命令**不执行**,单独运行:

```sh
uv run pytest -m e2e          # 只跑 e2e
```

pytest 配置在 `backend/pyproject.toml` 的 `[tool.pytest.ini_options]`:`testpaths`、`pythonpath`、`asyncio_mode`、标记注册与默认排除都在那里。

## 数据库迁移

Alembic 连接串取自 `APITEST_DATABASE_URL_SYNC`(见 [数据模型](../design/数据模型.md) 的迁移约定)。Windows 终端默认 GBK,带中文注释的 alembic 环境需显式 UTF-8:

```sh
PYTHONUTF8=1 uv run alembic upgrade head    # 应用迁移到开发库 apitest
PYTHONUTF8=1 uv run alembic revision --autogenerate -m "..."
PYTHONUTF8=1 uv run alembic downgrade -1
```

baseline 迁移会写入种子用户 `admin`(MVP 无认证,`get_current_user()` 返回它)。CRUD 集成测试自动创建独立测试库 `apitest_test` 并重放迁移,结束即删,不碰开发库。

## 启动进程与验收数据

MVP 闭环涉及四个进程(均在 `backend/` 下):

```sh
PYTHONUTF8=1 uv run alembic upgrade head              # 1. 迁移
uv run uvicorn app.main:app --port 8000               # 2. API
PYTHONUTF8=1 uv run celery -A app.tasks.celery_app worker -Q execution,default -l info -P solo
                                                       # 3. worker(Windows 用 solo 池)
PYTHONUTF8=1 uv run celery -A app.tasks.celery_app beat -l info
                                                       # 4. beat:每分钟触发调度 tick(issue #37)
```

> **beat 必须单实例**。beat 负责触发定时调度的每分钟 tick,多实例会重复触发,
> 造成同一调度被并发派发。`FOR UPDATE SKIP LOCKED` 只是误配时的兜底,不是扩容
> 手段 —— 水平扩容只针对 worker,beat 严格 1 个(架构设计 §9)。本地起了 beat
> 又在别的机器/容器里跑一份,是这类事故最常见的原因。

> **本地验证调度动线时把 tick 与执行拆成两个 worker**。solo 池一次只跑一个任务,
> 单 worker 同时消费 `execution,default` 两个队列时,一个长执行(如 75 秒的慢
> 步骤)会把排在后面的 tick 任务饿住 —— tick 被处理时 run 已结束,重叠跳过
> (`overlap`)永远观察不到。拆开即可复现生产行为:
>
> ```sh
> uv run celery -A app.tasks.celery_app worker -Q execution -l info -P solo -n exec@%h
> uv run celery -A app.tasks.celery_app worker -Q default -l info -P solo -n tick@%h
> ```

seed 脚本一键灌入 / 重置验收数据(默认项目 + dev 环境 + 变量 + 「登录提取 token → 携带 token 查询」2 步用例),重复执行即重置:

```sh
APITEST_SEED_BASE_URL=http://127.0.0.1:9000 PYTHONUTF8=1 uv run python scripts/seed.py
```

被测服务任意实现,需提供 `POST {{base_url}}/login` 与 `GET {{base_url}}/profile`(凭据 `demo_user`/`demo_pass`)。触发后轮询 `GET /api/v1/runs/{run_id}` 与 `GET /api/v1/runs/{run_id}/steps` 看汇总与逐步明细。

## 与 compose 的分工

compose 只放**无状态难以本地直装**的基础设施(PG / Redis);有状态的应用数据卷由 compose 的 named volume 管理(`pgdata` / `redisdata`),`docker compose down` 保留数据,`docker compose down -v` 才清空。后续生产部署形态见 [架构设计 §9](../design/架构设计.md)。
