# 用例目录采用独立目录表,而非统一节点表

用例管理要改造成「左树右表」(见 issue #20),目录需要落库。我们决定:**新增独立的目录表**(project_id / name / parent_id / 排序),用例表只加一个可空的 `folder_id`;而不是给用例/目录建统一节点表、靠 `parent_id` 混排(Apifox 式「接口与用例同树」)。

**为什么**:统一节点表要求每个节点区分「目录/用例」两种类型,树查询、环检测、深度校验都要处理异构子节点,而我们的树里用例永远是叶子 —— 独立表让目录树只查一张小表,用例与目录的关系就是一个普通外键;「未分类」用 `folder_id IS NULL` 表达,连哨兵行都不用。目录树深度限制 3 级。

**否决的方案**:
- 统一节点表(parent_id 混排)—— 灵活(用例可挂子节点、接口与用例同树),但那对应 MeterSphere/Apifox「接口定义 → 用例引用」的产品模型,我们已明确不做引用模式;为不做的功能付数据模型复杂度不划算。
- 标签/平铺 + 过滤 —— 不解决「用例一多不可用」的主问题,只缓解。

**后果**:若未来真要引入「接口定义」或目录级变量继承,目录表需要演进(加作用域/类型列),但比把用例表重构成节点表便宜得多。
