# 前端设计(MVP)

> `frontend/` · Vue 3 + TypeScript + Vite + Pinia + Vue Router。第一阶段(spike #1)验证了引擎与执行管道,本篇定义第一条可视化闭环的形态。来源:grilling 第二阶段三轮对齐(全部按推荐项锁定)。

## 1. 范围

**做**(spec user stories 1–20 的 UI 化,四页闭环):

| 页面 | 能力 |
|---|---|
| 环境与变量 | 环境列表 + 环境级/项目级变量管理;`is_secret` 值打码,点眼睛临时显示 |
| 用例管理 | 用例列表 + 用例详情(结构化步骤表单 ⇄ DSL 源码双 Tab)+ 保存(保存即产生新版本) |
| 触发执行 | 选环境触发(202)→ 跳转报告详情;运行中可取消 |
| 执行报告 | 报告列表(回看历史)+ 详情(汇总、步骤时间线、请求/响应快照、断言明细) |

**不做**:登录页(后端免认证,种子用户)、Playwright e2e、SSE(轮询)、项目管理独立页(只做选择器 + 新建弹窗,删改走 Swagger)。

> 注:结构化 DSL 表单最初列为「不做」(先让用户写原生 JSON 反哺 DSL 设计);JSON 编辑器攒到用户反馈后已于 2026-10 补上(见 §6.1)。

## 2. 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 组件库 | Element Plus | 重表格重表单的 admin 形态,中文生态最成熟,无需设计投入 |
| HTTP | `openapi-fetch` + `openapi-typescript` | 与后端自动生成的 OpenAPI 文档直连,类型零手工同步(API设计 §9)。注:openapi-typescript 7.x 的 peer 声明只到 TS 5,生成器 CLI 与宿主 TS 版本实际解耦,`.npmrc` 里 `legacy-peer-deps=true` 放行 |
| DSL 编辑 | CodeMirror 6 + `@codemirror/lang-json` | 轻量、JSON 语法校验成熟 |
| 测试 | Vitest + jsdom + @vue/test-utils | 与 Vite 同族;两条缝见 §7 |
| 状态 | Pinia(已装) | store 承载全部业务逻辑,组件薄 |

**开发代理**:Vite dev server 把 `/api` 代理到 `http://127.0.0.1:8000`,免 CORS;生产部署形态不在本篇范围。

## 3. 类型生成流程

后端 FastAPI 自动产出 `/openapi.json`(根路径;每个端点显式 `response_model` + `status_code`,错误写进 `responses` —— 这是后端契约,见 API设计 §9)。前端:

```
npm run gen:api   # 后端在跑时执行:拉 openapi.json → openapi-typescript → src/api/schema.d.ts
```

- `schema.d.ts` **提交进仓库**:类型变了在 code review 里可见。
- 后端改了响应结构而前端未重新生成 → `openapi-fetch` 的类型与运行时不符,type-check 未必能全拦;MVP 靠约定(后端改响应的 PR 必须附带重新生成),CI 校验留到有 CI 时补。

## 4. 布局与路由

经典 admin 布局:**左侧固定 sidebar** + **顶栏项目选择器**。

| 路由 | 页面 |
|---|---|
| `/cases` | 用例列表(默认首页) |
| `/cases/:id` | 用例编辑(步骤表单 ⇄ DSL 源码,§6.1) |
| `/environments` | 环境与变量 |
| `/runs` | 报告列表 |
| `/runs/:id` | 报告详情 |

**项目切换**:当前项目 id 存 Pinia 全局 store(持久化到 localStorage),顶栏选择器切换后整站数据重取;无项目时引导先创建。新建项目走顶栏弹窗(名称 + 描述)。

## 5. 状态层

每个资源一个 store,store 是唯一的业务逻辑所在(组件只做展示与事件转发):

- `projectStore`:项目列表、当前项目 id。
- `environmentStore` / `variableStore` / `caseStore`:各自资源的列表与 CRUD 状态。
- `runStore`:触发、轮询(run + steps 两个轮询合并:steps 变更时才重取)、取消。

API client 通过 store 的工厂函数注入,测试时换 mock 实现 —— 与后端「EngineContext 注入」同构,这是 store 缝可测的前提。

## 6. 执行与报告动线

1. 用例编辑页「执行」→ 弹窗选环境(必选,默认上次用的)→ `POST /projects/{pid}/runs`(202)→ 路由跳 `/runs/{run_id}`。
2. 报告详情每 **2s** 轮询 `GET /runs/{rid}` + `GET /runs/{rid}/steps`;run 到终态(`RUN_TERMINAL_STATUSES`)停轮。轮询逻辑在 `runStore`,组件不感知。
3. 运行中顶部状态条:状态、已耗时、「取消」按钮(→ `POST /runs/{rid}/cancel`)。
4. 步骤时间线:每步状态/耗时/断言通过数,展开看请求/响应快照(含截断标记)与提取到的变量;skipped 步骤显示原因。

## 6.1 用例详情:编排 | 源码工作台

用户反馈 JSON 编辑器不便查看/编辑请求头、URL、请求体,先补了结构化步骤表单;平台化改版(issue #19)将其升级为**编排 | 源码双视图工作台**(调研 §B1,Apifox/MeterSphere 的「左步骤列表 + 右详情」形态)。类型在 `src/types/dsl.ts`,与后端 `app/engine/dsl.py` 对齐。

**编排视图**(默认):左侧紧凑步骤列表(拖拽排序、行内 ⊕ 插入/复制/调试/删除、未保存小圆点),右侧选中步骤详情面板(`StepDetail`:请求行 + Params/Headers/Body 子 tab,提取/断言/重试平铺),全局配置(用例变量/超时/失败即停)收进抽屉(`ConfigDrawer`)。

**单步调试**:每步行内「调试」按钮 → `POST /cases/{cid}/steps/{sid}/debug?environment_id=`(同步端点,不走 Celery),结果渲染在详情面板下方的 `DebugPanel`:实际请求(变量替换后)+ 真实响应快照分栏展示,分栏可切**上下/左右/不分屏**(Apifox「分隔」),断言逐条 PASS/FAIL 与提取结果独立 tab。约定:

- 调试端点执行的是**已保存版本**,所以脏步骤先自动保存再调试(校验失败则中断,错误回显在编辑器上方)。
- 顶部常驻**环境选择器**(调试目标),与变量页共用环境 store 的选中态。
- 调试单步不跑前序步骤,提取变量的作用域是单步的 —— 与报告语义区分。

**dsl 对象是事实来源**。表单就地编辑它(深度 watch 刷新源码文本);源码文本每次改动实时 parse,合法才回写 dsl(用户文本原样保留),非法则标语法错误并**阻止切回编排视图**(dsl 留在上一份有效值)。

其余约定:

- 加载与保存都走 `normalizeDsl`:缺省字段补默认值(config/headers/params/retry/extract.required 等),未知字段原样保留(spread 优先、已知字段覆写)—— 用户手写的扩展字段不丢。深校验仍归后端 `parse_dsl`(§8 不变)。
- KV 编辑(headers/params/变量/body 的 form-data、urlencoded)行内编辑**就地改 dict**:未触碰的值类型不动(变量可以是数字/布尔);只有增删行才重建。这延续 VariableTable「行内编辑直接改对象、增删行发新数组」的缝。
- `KvEditor` 只在 dict **引用变化**时重建行(载入/normalize),避免行内输入时光标跳动。
- 脏点按步骤比对:载入/保存时对每步 JSON 做快照,行内编辑实时比对(与整份 dsl 的 `isDirty` 共用一套快照,后者供调试前自动保存判断)。
- 步骤 id 用 `nextStepId` 取不冲突的 `step-N`(复制步骤也走它换新 id);断言 `expected` 用文本框(引擎 `_eq`/`_ordering` 有数字强制转换,无需前端分型)。
- 拖拽用 `vuedraggable`,仅调序、不改层级(MeterSphere「拖拽同时改层级」明确不抄,调研 §F)。

## 7. 测试策略(两条缝)

与后端「引擎缝 + 应用缝」同思路——业务逻辑在 store,组件测试只钉关键渲染:

| 缝 | 测什么 | 手段 |
|---|---|---|
| **缝 1:Pinia store** | 注入 mock API client,验证状态迁移:列表加载/错误、**轮询启停**(终态停轮、取消后停轮)、CRUD 后列表刷新 | Vitest + mock client,毫秒级 |
| **缝 2:关键组件挂载** | 报告步骤时间线渲染(含截断/断言失败态)、DSL 编辑器校验错误回显、编排工作台双向同步(URL 等改动进 dsl/随 PATCH 提交、非法 JSON 阻止切视图、脏点显隐、调试先保存再调端点)、步骤详情面板(Body 类型切换/提取断言行增删)、调试结果分栏与断言渲染、KV 行内编辑与增删行、`is_secret` 打码切换 | @vue/test-utils |

不测:Element Plus 自身行为、纯展示模板。不引入 Playwright(页面稳定后评估)。

## 8. 错误处理约定

- `openapi-fetch` 外包一层 client 工厂,统一拦截错误响应:后端格式恒为 `{"error":{code,message,details}}`,非 2xx → ElMessage 弹出 `message`(开发模式附 `code`)。
- DSL 保存校验:前端只查 JSON 语法(CodeMirror 错误标线);**业务校验全交给后端** `parse_dsl` —— 400 时把 `details` 的字段定位回显在编辑器上方。不引 ajv/JSON Schema:pydantic 导出 schema 给前端是双份真相,违背单一来源。

## 9. 未决问题

- 报告列表要不要按用例筛选(端点暂无 filter 参数)—— 等真实使用反馈。
- CI 中的 schema 同步校验(npm script 比对自己重新生成的 diff)—— 有 CI 后补。
- 步骤表单的 KV 型变量值目前只能写字符串(未触碰的值保留原类型)—— 若用户反馈需要编辑数字/布尔/JSON 值,再给 KvEditor 加类型选择。

| 阶段 | 内容 | Issue |
|---|---|---|
| ① ✅ 已实施 | 用例详情调试工作台:`编排 \| 源码` 双视图;左紧凑步骤列表(拖拽/⊕ 插入/复制/脏点/调试/启用/删除)+ 右详情面板(请求 + Params/Headers/Body 子 tab;提取/断言/重试平铺);顶栏常驻环境选择器;后端新增**同步**单步调试端点;调试结果上下分栏(可切左右/不分屏),断言/提取独立 tab(实现形态见 §6.1) | #19 |
| ② | 用例目录树(左树右表):独立目录表 + 用例挂目录(选型见 ADR-0001),未分类虚拟节点,树操作含拖拽移动(move 端点做环检测、深度限 3);导航措辞改「接口用例 / 测试报告」 | #20 |
| ③ | 测试报告改版:统计卡行 + 可展开步骤列表,时间线退役;调试结果渲染组件与 ① 复用 | #21 |

**不变的原则**:DSL-first(视图只是 DSL 的投影)、深校验归后端 parse_dsl、Element Plus 不换库、术语以根目录 CONTEXT.md 为准。明确不做:Flow 画布、控制器全集、接口定义引用模式、多标签页、报告分享链接、暗色/换库。
